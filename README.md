# NMR / AI

A student tutorial on extracting vector polarization from NMR spectra, based on the [gen-NMR research pipeline](https://github.com/zetanaut/gen-NMR).

The three learning phases are:

1. Build a training-data generator: match experimental spectra, characterize noise, vary physical parameters, and generate enough independent configurations and realizations.
2. Design a DNN/CNN: understand the existing physics-guided multiscale network and compare its capability with its inference cost.
3. Train and evaluate: grouped splits, validation and stopping, bias, residual width, RMSE, and relative error at a stated polarization scale.

The website includes an interactive bias/precision lab, actual training curves and held-out residual histograms, local-band metrics near +5% P, runnable examples, and student assignments. It assumes basic Python and physics, with no prior neural-network experience.

## Run the Python labs

The full coding labs require instructor-provided access to the research repository or a source bundle; the reading and embedded plots need no research checkout. Keep `NMR-AI/` and `gen-NMR/` as sibling directories. Activate the research environment. From `gen-NMR/`:

```bash
python ../NMR-AI/tools/analyze_predictions.py \
  ml/Models/RGC_vector_absolute_100k/test_predictions.csv \
  --p0 0.05 --half-width 0.005

python ../NMR-AI/tools/benchmark_network.py \
  --architecture physics_multiscale --device cpu --batch-size 1
```

The first command needs local prediction artifacts; the page also explains how to generate and train a new smoke dataset. NumPy is sufficient for the analysis helper. The benchmark requires the research checkout and its dependencies; use `--project-dir /path/to/gen-NMR` if the directories are not siblings. It times architecture forward passes with random weights, excluding preprocessing and transfers, and makes no trained-accuracy claim.

Source for the recorded research experiments: `gen-NMR` revision `496f70a7220aa40e382f4646c1d7035b35907399`. Ensure that revision is available in the research repository before teaching the newest flags. Large datasets, weights, and experimental scans stay in the research workspace; they are not included here.

## Data provenance and interpretation

`docs/assets/results.js` is a compact aggregate of three saved **synthetic** experiments. It includes run configurations, grouped split counts, training histories, residual histograms, summary metrics, and SHA-256 hashes of source prediction CSVs. No raw experimental scans or individual prediction rows are embedded.

The snapshot can be regenerated by a maintainer with the original artifacts:

```bash
python tools/export_results.py --project-dir ../gen-NMR
```

The snapshot recomputes bias, population residual SD (`ddof=0`), RMSE, MAE, and the 95th-percentile absolute error from the prediction CSVs in float64. Small rounding differences from the trainer's float32 metrics are expected. The identity `RMSE² = bias² + width²` uses the same events and population SD. Relative values use a fixed nonzero reference `P0`; local-band metrics select signed truth values before computation. No uncertainty intervals are inferred from residual width.

The source artifacts correct two inconsistencies in older handoff prose: the shifted restricted-pool bias is approximately `-0.0000240`, and the broad-pool test partition has 10,051 events (10,045 is the count above the relative-error floor).

These are development results, not a final independent experimental benchmark. The `0.0005` fractional-P RMSE target remains unmet. The page distinguishes implemented features from suggested noise-model extensions and simulator-only oracle diagnostics.
