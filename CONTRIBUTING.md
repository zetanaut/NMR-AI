# Working on the tutorial

For learning exercises, start with the
[walkthrough](https://zetanaut.github.io/NMR-AI/walkthrough.html).
This guide covers code checks and maintenance of the published lessons.

## Check a change

Use the environment from the [README](README.md#set-up), then run:

```bash
python -m unittest discover -s tests -v
python -m http.server 8000 --bind 127.0.0.1 --directory docs
```

Open [the local walkthrough](http://127.0.0.1:8000/walkthrough.html) and the pages
you changed. Check desktop and narrow screens, figures, links, copy buttons,
and readability with JavaScript disabled. Stop the server with Ctrl+C.

Keep the README as the entry point and the walkthrough as the ordered command
guide. Put derivations and supporting detail in [docs/reference/](docs/reference/README.md).
Each command should explain what to inspect and where to continue.

## Preserve the scientific definitions

Read the relevant [reference pages](docs/reference/README.md) before changing
the physics, fitting, preprocessing, or reported results. Preserve the exact
500-bin grid and distinguish recorded units from volts. Keep measured data,
fitted polarization estimates, and newly sampled simulator labels distinct.

The included raw CSVs and the original ND3 excerpt are preserved byte for byte.
The working ND3 file is a reproducible interpolation. If its preparation code
changes, check the derivation and apply the same observation operator to the
model. A full generator change requires regenerated data and retraining before
updating its reported results.

Store generated datasets, checkpoints, full fit products, and local reviews in
`local-results/`. Commit only the selected example and reference artifacts
needed by the lessons. The repository runs independently of other projects.

## Update reference results

Students plot their own fits with `tools/plot_fit.py`. The following exporters
write to `docs/` and are for updating the website's saved reference results.
They verify data, code, saved predictions, and figures before publication.
Keep their checks intact; a source mismatch requires investigating the change.

| Published result | Export command and required input |
| --- | --- |
| Measured baseline | `export_baseline_example.py --fit-dir FIT_DIR` |
| Single-site fits and generation | `export_signal_matching.py --fit-dir FIT_DIR --dataset DATA.npz` |
| Material examples | `export_material_examples.py --butanol-fit-dir FIT_DIR --nd3-fit-dir FIT_DIR` (either material may be supplied) |
| Experiment-based network | `export_lineshape_training.py --runs-dir RUNS_DIR` |
| MLP/DNN/CNN comparison | `export_model_comparison.py --runs-dir RUNS_DIR` |
| Additional CNN runs | `export_results.py` (uses the benchmark paths) |

Run each as `python tools/COMMAND`. Consult `--help` and the corresponding
reference page for input reports and protocol settings. The training runner and
exporter must use the same runs directory.

The material pages are generated by `export_material_examples.py`; the
lineshape network section is generated by `export_lineshape_training.py`.
Edit their text templates as well as the displayed pages. Other exporters
replace figures, tables, or data within page markers. Preserve those markers.

The original ND3 source is an internal reader resource in `tools/_data/`.
To check preparation without overwriting the included working example:

```bash
python tools/prepare_uva_nd3.py --output local-results/uva-nd3-check.json
```

Create `local-results/` first if this is a fresh checkout. Compare the generated
file with `examples/uva-nd3.json`; it should be identical.

The GitHub Pages workflow publishes `docs/` when that directory changes on
`main`. The site is static: no build, external font, or CDN is required. After
publishing, verify the live pages against the checked-in assets.
