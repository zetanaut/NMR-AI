Advanced lab · after the nine-step walkthrough

Improve the DNN where it matters:
20% to 30% polarization.

Your job is to improve prediction accuracy in the signed bands −30% to −20% and +20% to +30%. Restricting the intended range simplifies the problem and lets you concentrate training data where accuracy matters. A model trained only in those bands is only for use there; it has no demonstrated validity elsewhere. First change training-data size and distribution. Only after finding that limit may you add one DNN layer.

What makes this different from the walkthrough?

The walkthrough teaches the full pipeline. This lab asks you to make decisions: where to sample, how much data to generate, what metric to optimize, when more data stops helping, whether a slightly more complex DNN improves the focused region, and how much the answer changes with random seed.

Rules for a defensible comparison
RuleWhy it matters
Freeze independent test sets before tuningPrevents choosing the design that happens to flatter one test draw.
Keep preprocessing, optimizer, architecture and seeds fixed during the data-only phaseIsolates the effect of more data and changed sampling distribution.
Report positive and negative bands separatelyA small pooled score can hide a sign-dependent bias.
State each model's training coverage and intended useA focused-only model must not be used where it has no training data; broader use requires broader training and evaluation.
Record rows, configurations, parameters, best epoch and wall timePerformance has a computational and statistical cost.
01

Declare the objective first

Write the target metric before training.

Use the matching report from walkthrough step 4. All commands below assume it exists at local-results/walkthrough/single-site/matching_report.json. Use fresh output paths if your walkthrough folder is different.

Your primary target is regional error in these truth-label bands:

  • Positive target: 0.20 ≤ P < 0.30
  • Negative target: -0.30 ≤ P < -0.20

For each target band, report event count, bias, residual width, RMSE, MAE and 95th-percentile absolute error. Use percentage points: multiply fractional-P errors by 100. If you train for broader use, also measure overall error and the regions 0.05 ≤ |P| < 0.10 and 0.40 ≤ |P| < 0.50 on an independent full-range test set. Testing alone cannot make an untrained region a valid operating range.

Deliverable

A one-paragraph measurement contract: target P region, primary metric, each model's intended operating range, checks appropriate to that range, allowed changes in each phase, and the fixed test-set names you will use.

02

Do not tune on the final evidence

Generate focused and full-range test sets.

The two focused sets use different random seeds. Their signs are generated separately and combined so the target region has enough statistics. A separate full-range set checks broad and mixed models intended for broader use; it does not extend the operating range of a focused-only model. All three remain independent of training data.

Run

03

Change the data, not the model

Build focused, broad and target-enriched training datasets.

The generator samples uniformly over one interval. Focused rows simplify a model intended only for the two target bands. Broad rows support a model intended for the full working range, and mixing broad and focused rows tests whether extra target-band sampling helps a broad model. Compare equal row counts when studying distribution.

Run

mkdir -p local-results/advanced/data

# Broad baseline distribution.
python tools/generate_matched_data.py --matching-report "$REPORT" \
  --num-samples 6000 --num-configurations 300 --p-min -0.60 --p-max 0.60 \
  --seed 42 --output local-results/advanced/data/broad-6k.npz

# More broad rows for a 12k-row size and distribution comparison.
python tools/generate_matched_data.py --matching-report "$REPORT" \
  --num-samples 6000 --num-configurations 300 --p-min -0.60 --p-max 0.60 \
  --seed 45 --output local-results/advanced/raw/broad-extra-6k.npz
python tools/combine_datasets.py --output local-results/advanced/data/broad-12k.npz \
  local-results/advanced/data/broad-6k.npz local-results/advanced/raw/broad-extra-6k.npz

# Focused training rows in both target bands.
python tools/generate_matched_data.py --matching-report "$REPORT" \
  --num-samples 3000 --num-configurations 150 --p-min 0.20 --p-max 0.30 \
  --seed 43 --output local-results/advanced/raw/focus-pos-3k.npz
python tools/generate_matched_data.py --matching-report "$REPORT" \

Scope of the models

focused-6k has training data only in the two target bands. Use its results only to study predictions in those bands. It cannot tell from an unknown spectrum alone whether the true P lies inside them. If you need predictions elsewhere, train and validate with coverage there, as in broad-6k, broad-12k and mixed-12k. Compare broad-6k with broad-12k for size, then broad-12k with mixed-12k for sampling distribution at the same row count.

04

First comparison: DNN only

Train the same DNN on each training distribution.

Do not change the architecture yet. Use the same optimizer settings and seeds so the comparison is about training data.

Run

mkdir -p local-results/advanced/models
for name in focused-6k broad-6k broad-12k mixed-12k; do
  python tools/train_model.py \
    --data local-results/advanced/data/${name}.npz \
    --output-dir local-results/advanced/models/dnn-${name} \
    --architecture dnn --epochs 80 --patience 12 \
    --learning-rate 0.0001 --seed 42 --batch-order-seed 42 \
    --device cpu --threads 2 --defer-test
done

If you use a GPU, keep the same device across the compared runs or record the difference. The selected checkpoint still comes from validation loss on that run's training dataset, not from the frozen tests.

05

Measure what changed

Evaluate each model in its intended range.

Run every model on both frozen focused tests. Run only the broad and mixed models on the full-range test. Analyze the positive and negative target bands separately. The helper uses signed bands centered at p0; --p0 0.25 --half-width 0.05 selects 20% to 30%.

Run

mkdir -p local-results/advanced/predictions local-results/advanced/reports
for model in dnn-focused-6k dnn-broad-6k dnn-broad-12k dnn-mixed-12k; do
  tests="focused-test-a focused-test-b"
  if [ "$model" != dnn-focused-6k ]; then tests="$tests full-range-test"; fi
  for test in $tests; do
    python tools/predict.py \
      --model-dir local-results/advanced/models/${model} \
      --data local-results/advanced/tests/${test}.npz \
      --output local-results/advanced/predictions/${model}-${test}.csv
    python tools/analyze_predictions.py \
      local-results/advanced/predictions/${model}-${test}.csv \
      --p0 0.25 --half-width 0.05 \
      > local-results/advanced/reports/${model}-${test}-pos.json
    python tools/analyze_predictions.py \
      local-results/advanced/predictions/${model}-${test}.csv \
      --p0 -0.25 --half-width 0.05 \
      > local-results/advanced/reports/${model}-${test}-neg.json
    if [ "$test" = full-range-test ]; then
      for region in 0.075 0.45 -0.075 -0.45; do
        case "$region" in 0.075|-0.075) width=0.025 ;; *) width=0.05 ;; esac
        python tools/analyze_predictions.py \
          local-results/advanced/predictions/${model}-${test}.csv \
          --p0 "$region" --half-width "$width" \
          > local-results/advanced/reports/${model}-${test}-${region}.json
      done
    fi
  done
done

Read signed_p_band in each JSON report and pooled for the full-range test. The focused tests provide large target-band counts for every model. The full-range test checks the models trained for broader use; its four additional reports cover both signs of the two outside bands. If positive and negative results disagree, report them separately.

Make a compact comparison table

python - <<'PY'
import json
from pathlib import Path
base = Path('local-results/advanced/reports')
for model in ['dnn-focused-6k', 'dnn-broad-6k', 'dnn-broad-12k', 'dnn-mixed-12k']:
    tests = ['focused-test-a', 'focused-test-b']
    if model != 'dnn-focused-6k':
        tests.append('full-range-test')
    for test in tests:
        row = [model, test]
        if test == 'full-range-test':
            pooled = json.loads((base / f'{model}-{test}-pos.json').read_text())['pooled']
            row.append(f"pooled RMSE={pooled['rmse_percentage_points']:.3f} pp")
        for sign in ['pos', 'neg']:
            band = json.loads((base / f'{model}-{test}-{sign}.json').read_text())['signed_p_band']
            row.append(f"{band['n']} rows, RMSE={band['rmse_percentage_points']:.3f} pp, "
                       f"bias={band['bias_percentage_points']:.3f} pp")
        print(' | '.join(row))
    if model != 'dnn-focused-6k':
        for region in ['0.075', '-0.075', '0.45', '-0.45']:
            band = json.loads((base / f'{model}-full-range-test-{region}.json').read_text())['signed_p_band']

06

How much data is enough?

Build learning curves by adding rows.

Repeat the data-only comparison at several sizes. A useful sequence is 2k, 6k, 12k and 24k. At each size, compare focused, broad and mixed sampling for target-band accuracy. Keep the DNN and training settings fixed. Record target-band RMSE on both test seeds, validation loss, best epoch and training time. Record full-range error only for models trained for that range.

Suggested learning-curve grid
DatasetCompositionQuestion
focused-NHalf positive 20–30%, half negative −30% to −20%How well can a model restricted to these bands perform there?
broad-NUniform −60% to +60%Does more broad coverage improve the target band?
mixed-NBroad rows plus extra rows in both target bands, totaling NDoes target enrichment help at the same row budget while preserving accuracy elsewhere?

Stop claiming improvement when the two independent test seeds disagree as much as the apparent gain, or when target-band error plateaus while cost continues to grow. That plateau is part of the result, not a failure of the lab.

07

Then change the model

Add one hidden layer to the DNN and compare fairly.

Only after choosing the best data-only distribution should you use the deeper DNN. The new architecture is dnn_extra: a four-hidden-layer dense network with an added intermediate layer. Compare it against the best ordinary dnn trained on the same dataset.

Run

BEST_DATA=local-results/advanced/data/mixed-12k.npz
python tools/train_model.py \
  --data "$BEST_DATA" \
  --output-dir local-results/advanced/models/dnn-extra-mixed-12k \
  --architecture dnn_extra --epochs 80 --patience 12 \
  --learning-rate 0.0001 --seed 42 --batch-order-seed 42 \
  --device cpu --threads 2 --defer-test

The command uses mixed-12k as an example. If you select another dataset, change both BEST_DATA and the output name, then compare against the ordinary DNN trained on that same dataset. Evaluate on the focused tests; use the full-range test only when that dataset includes broad training coverage. If the extra layer reduces training loss but not target-band test RMSE, report overfitting or optimization limits instead of calling it an improvement.

Fair comparison

The deeper DNN must beat the best data-only DNN, not merely the original broad baseline. Report parameter count from provenance.json, best epoch, training time and both focused test seeds.

08

Statistics are part of the result

Use two generated test sets to estimate metric stability.

For every final candidate, compare the two focused tests side by side. The difference between focused-test-a and focused-test-b is a warning about finite simulated statistics and seed dependence. It is not an experimental uncertainty, but it tells you how much confidence to place in small metric differences.

For broad and mixed models, use the independent full-range-test to report pooled error and the prespecified checks at 0.05 ≤ |P| < 0.10 and 0.40 ≤ |P| < 0.50. Check event counts in each band; generate more independent full-range test rows if a band is too sparse. The focused-only model has no claim outside its training bands. If broader use matters, compare the broad and mixed models there and report any loss of accuracy.

How to discuss limits

Possible limits include insufficient target-band examples, too few independent configurations, validation not aligned with the target metric, DNN capacity, optimization, noise ambiguity, or simulator mismatch. Do not assume more data is the cure until the learning curves show it. Do not assume a deeper DNN is the cure until it beats the best data-only DNN on both focused test seeds.

Final deliverable

Write the investigation report.

  1. Objective: define the signed target bands, primary metric and intended operating range of each model.
  2. Data-only result: compare focused, broad and mixed datasets across at least two sizes, keeping row counts matched when comparing distributions.
  3. Learning curve: plot target-band RMSE versus training rows and state where more data stops helping.
  4. Seed stability: show results on both focused test sets and discuss whether differences are meaningful.
  5. Complexity result: compare dnn and dnn_extra on the same best dataset.
  6. Operating range: report full-range and outside-band errors only for models trained with broad coverage; state explicitly that the focused-only model is not for use outside its training bands.
  7. Limits: state what you could not improve using data distribution or one added layer.

The goal is not to make every number smaller. The goal is to learn which knob matters, which result is stable, and where the evidence says to stop.
